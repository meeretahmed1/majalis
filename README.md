# مجالس — من المجلس إلى الحياة

منصة تعليمية عربية (RTL) لدراسة الكتب التراثية والإسلامية مجلساً مجلساً: فيديو/صوت/نص، ملخص، خريطة ذهنية، بطاقات مراجعة بنظام التكرار المتباعد، اختبارات قصيرة، ملاحظات وخواطر وأسئلة خاصة بكل مستخدم، وربط كل مجلس بتطبيق حياتي قابل للمتابعة.

هذا المستودع هو **الكود الإنتاجي** المبني على Next.js + TypeScript + Prisma + PostgreSQL، المقابل للنموذج التفاعلي (Prototype) الذي جربته سابقاً. لا توجد بيانات وهمية ثابتة في الواجهات؛ كل صفحة تُقرأ من قاعدة البيانات فعلياً.

---

## 1. لماذا هذه التقنيات؟

| التقنية | السبب |
|---|---|
| **Next.js 14 (App Router) + TypeScript** | يجمع الواجهة والـ API في مشروع واحد، مع Server Components لعرض بيانات مباشرة من قاعدة البيانات دون طبقة وسيطة، وType-safety تمنع أخطاء كثيرة قبل التشغيل |
| **PostgreSQL + Prisma** | قاعدة بيانات علائقية تناسب الهيكل الهرمي (كتاب ← باب ← مجلس ← روابط)، وPrisma يعطي استعلامات آمنة الأنواع وسهولة تعديل المخطط عبر `db push` |
| **NextAuth (Credentials) + RBAC يدوي** | تسجيل دخول آمن بكلمة مرور مشفّرة (bcrypt)، مع تخزين الدور (Admin/Teacher/Student) داخل الجلسة وفحصه في كل مسار API عبر `requireRole` و`assertOwnership` |
| **Tailwind CSS** | تصميم متجاوب وRTL سريع دون كتابة CSS يدوي مكرر |
| **Vitest** | اختبارات سريعة لا تحتاج إعداداً معقداً، مناسبة لمنطق مثل جدولة المراجعة المتباعدة |

## 2. التشغيل محلياً

### المتطلبات
- Node.js 20 أو أحدث
- قاعدة بيانات PostgreSQL (محلية عبر Docker، أو سحابية مثل [Neon](https://neon.tech) أو [Supabase](https://supabase.com) — كلاهما له خطة مجانية تكفي للتجربة)

### الخطوات

```bash
# 1) تثبيت الحزم
npm install

# 2) نسخ متغيرات البيئة وتعديلها
cp .env.example .env
# افتح .env وضع فيه رابط قاعدة بياناتك الفعلي، ومفتاح NEXTAUTH_SECRET
# لتوليد مفتاح عشوائي: openssl rand -base64 32

# 3) إن لم يكن لديك PostgreSQL محلي، شغّله سريعاً عبر Docker:
docker run --name majalis-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=majalis -p 5432:5432 -d postgres:16

# 4) إنشاء الجداول في قاعدة البيانات من مخطط Prisma
npm run db:push

# 5) زرع البيانات التجريبية (حساب أدمن + طالب + كتاب بثلاثة مجالس حقيقية)
npm run db:seed

# 6) تشغيل المشروع
npm run dev
```

افتح `http://localhost:3000`.

**حسابات تجريبية بعد الزرع:**
- **أدمن:** `admin@majalis.local` / `Admin@12345`
- **طالب:** `student@majalis.local` / `Student@12345`

سجّل دخولك كأدمن وستجد رابط "لوحة الإدارة" في الشريط العلوي.

### تشغيل الاختبارات
```bash
npm test
```
يغطي هذا: خوارزمية التكرار المتباعد (Spaced Repetition)، والتحقق من منع وصول مستخدم لبيانات مستخدم آخر (Ownership check).

### معاينة قاعدة البيانات بصرياً (اختياري)
```bash
npm run db:studio
```

## 3. كيف تضيف كتاباً أو مجلساً جديداً (بدون كود)

1. سجّل دخولك بحساب Admin.
2. من لوحة الإدارة (`/admin`) اضغط **"+ كتاب جديد"**، واملأ العنوان والنبذة. يُحفظ الكتاب كمسودة تلقائياً مع باب افتراضي باسم "الباب الأول".
3. داخل بطاقة الكتاب، اضغط **"+ مجلس جديد"** — سيُنشأ المجلس فوراً وتُفتح صفحة تحريره الكاملة.
4. في صفحة تحرير المجلس أضف: النص/رابط الفيديو، الملخص (نقاط قابلة للإضافة والحذف)، الخريطة الذهنية (نص بمسافات بادئة، كل مستوى فرعي بمسافتين إضافيتين)، البطاقات التعليمية، أسئلة الاختبار (مع تحديد الإجابة الصحيحة بالزر الدائري)، تطبيقات "من العلم إلى الحياة"، وأخيراً روابط بمجالس أخرى (سابق تلقائياً حسب الترتيب، وروابط يدوية أخرى مثل "يُراجَع قبله" أو "رأي آخر").
5. اضغط **"نشر المجلس"** ثم من صفحة الكتاب (`/admin/books/[id]`) اضغط **"نشر الكتاب"** ليظهر للطلاب في المكتبة.

كل الحقول تُحفظ فور مغادرتك للحقل (onBlur) أو فور الضغط على زر الإضافة — لا يوجد زر "حفظ" عام مطلوب لكل شيء.

## 4. النشر على الإنترنت (Deployment)

**الخيار الأبسط: Vercel + Neon/Supabase**

1. أنشئ قاعدة بيانات مجانية على [Neon](https://neon.tech) أو [Supabase](https://supabase.com) وانسخ رابط `DATABASE_URL`.
2. ادفع هذا المشروع إلى مستودع GitHub.
3. من [vercel.com](https://vercel.com) اربط المستودع، وأضف متغيرات البيئة الثلاثة (`DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL` = رابط نطاقك على Vercel).
4. بعد أول نشر، شغّل مرة واحدة من جهازك (بنفس `DATABASE_URL` السحابي):
   ```bash
   npm run db:push
   npm run db:seed
   ```
5. الموقع يعمل مباشرة على الرابط الذي يعطيك إياه Vercel.

**بديل: خادم خاص (VPS) عبر Docker** — أضف `Dockerfile` قياسي لـ Next.js (standalone output) مع حاوية PostgreSQL منفصلة أو مُدارة، ثم `docker compose up`. يمكنني إعداد هذا الملف إن قررت هذا المسار.

## 5. ما المُنجز فعلياً في هذه النسخة (MVP) وما المتبقي

### منجز ويعمل فعلياً (متصل بقاعدة بيانات حقيقية، لا بيانات وهمية):
- تسجيل الدخول/إنشاء حساب، وأدوار (Admin/Teacher/Student) مع صلاحيات مفصولة فعلياً في كل مسار API.
- المكتبة وصفحة الكتاب (مع نسبة تقدم حقيقية من قاعدة البيانات).
- صفحة المجلس بكل تبويباتها: المحتوى، الملخص، الخريطة الذهنية القابلة للطي، البطاقات (مع تسجيل تقييم الصعوبة وجدولة المراجعة القادمة عبر خوارزمية SM-2 مبسّطة)، الاختبار القصير (يُصحَّح على السيرفر فلا تُرسل الإجابة الصحيحة للعميل مسبقاً)، الملاحظات/الخواطر/الأسئلة الخاصة بكل مستخدم، و"من العلم إلى الحياة" مع زر الالتزام.
- روابط المجلس السابق/التالي (تلقائياً حسب الترتيب) والروابط اليدوية (متمم/مشابه/رأي آخر... إلخ).
- لوحة تحكم إدارة كاملة: إضافة كتاب، إضافة مجلس، تحرير كل عنصر فيه، النشر/إعادة للمسودة.
- لوحة المستخدم الشخصية (إحصائيات + "رحلتي من العلم إلى العمل").
- سجل تدقيق (Audit Log) لعمليات الإدارة الأساسية.

### للإصدارات القادمة (Roadmap) — كما ورد في طلبك الأصلي:
- تطبيق الهاتف (PWA / تطبيق مستقل).
- توليد الخرائط الذهنية والبطاقات تلقائياً من نص المجلس عبر ذكاء اصطناعي، مع مراجعة الأدمن قبل النشر.
- البحث الدلالي داخل الكتب، وقاموس المصطلحات التفاعلي.
- جلسة "راجع في 5 دقائق" وخطة المذاكرة الذكية كصفحات مستقلة (المنطق الأساسي لهما جاهز جزئياً في النموذج التفاعلي السابق ويحتاج نقله وربطه بقاعدة البيانات).
- مجموعات الدراسة، البث المباشر، الاشتراكات المدفوعة (معطّلة افتراضياً).
- محرر Drag & Drop للصفحة الرئيسية والهوية البصرية دون كود.

## 6. بنية المشروع (مختصرة)

```
prisma/schema.prisma        مخطط قاعدة البيانات الكامل
prisma/seed.ts               بيانات تجريبية حقيقية (أدمن + طالب + كتاب بثلاثة مجالس)
src/lib/                     Prisma client, المصادقة، RBAC، خوارزمية التكرار المتباعد
src/app/api/                 كل مسارات الـ API (عامة + إدارة + بيانات شخصية)
src/app/(pages)              الصفحات: الرئيسية، المكتبة، الكتاب، المجلس، لوحتي، تسجيل الدخول
src/app/admin/                لوحة تحكم الإدارة الكاملة
src/components/               مكوّنات Client التفاعلية (تبويبات المجلس، فورمات الإدارة)
tests/                        اختبارات Vitest
```

## 7. الأمان والخصوصية (مطبّق في الكود)

- كلمات المرور مشفّرة عبر bcrypt (لا تُخزَّن كنص صريح أبداً).
- كل مسار API لبيانات شخصية (ملاحظات، خواطر، أسئلة، تقدّم، بطاقات، التزامات) يتحقق أن المستخدم الحالي هو صاحب السجل فعلاً عبر `assertOwnership`، فلا يستطيع أي مستخدم قراءة بيانات غيره حتى لو خمّن المعرّف الصحيح.
- الصلاحيات الإدارية (`requireRole(["ADMIN", "TEACHER"])`) مفصولة تماماً عن صلاحيات الطالب.
- سجل تدقيق (`AuditLog`) يحفظ من قام بأي تعديل إداري وماذا فعل.
- **قبل الإنتاج الفعلي**، أضف أيضاً: تحديد معدل الطلبات (Rate Limiting) على `/api/register` و`/api/auth`، وفحص أنواع/أحجام الملفات إن أضفت رفع ملفات مباشر لاحقاً، وسياسة خصوصية وشروط استخدام (نصوص قانونية خارج نطاق هذا الكود).
